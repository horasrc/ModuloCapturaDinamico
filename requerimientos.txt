OBJETIVO
Crear un constructor de encuestas configurable, donde un usuario administrador pueda crear, editar, ordenar, duplicar, eliminar, publicar y versionar preguntas sin necesidad de modificar código.

- ASP NET MVC framework 4.8 
- jquery-3.7.1 
- css 
- Bootstrap v5.2.3
- Usar Bootstrap Icons.
- Diseño limpio, corporativo y responsive.
- Paleta principalmente blanca, gris claro, negro y rojo como color de acción.
- Evitar imágenes decorativas.
- Utilizar cards, accordions, badges, modals, dropdowns, offcanvas y componentes estándar de Bootstrap cuando tenga sentido.
- El diseño debe ser fácil de mantener y extender.

ESTRUCTURA DEL MÓDULO

1. ENCABEZADO
Mostrar:
- Nombre de la encuesta.
- Estado: Borrador / Publicada / Cerrada / Archivada.
- Botón "Vista previa".
- Botón "Guardar borrador".
- Botón "Publicar encuesta".


2. CONSTRUCTOR DE PREGUNTAS
Mostrar una lista de preguntas creadas.

Cada pregunta debe permitir:
- Editar.
- Duplicar.
- Eliminar.
- Cambiar de posición.
- Marcar como obligatoria.
- Configurar validaciones.
- Configurar lógica condicional.

Agregar botón:
"+ Agregar pregunta"

3. TIPOS DE PREGUNTA
El administrador debe poder elegir dinámicamente entre:

A. Opción única
- Radio buttons.
- Número de opciones variable.
- Solo una respuesta permitida.
- Posibilidad de agregar o eliminar opciones.

B. Selección múltiple
- Checkboxes.
- Número de opciones variable.
- Varias respuestas permitidas.
- Opción de habilitar "Otro".
- Si se selecciona "Otro", mostrar campo de texto.
- Permitir configurar mínimo y máximo de selecciones.

C. Texto libre
- Campo corto o textarea.
- Configurar máximo de caracteres.
- Configurar mínimo de caracteres.
- Mostrar contador de caracteres.
- Configurar si es obligatorio.

D. Sí / No
- Dos opciones simples.

E. Escala
- Permitir configurar escala, por ejemplo:
  1 a 5
  1 a 10

F. Fecha
- Selector de fecha.

G. Número
- Solo valores numéricos.
- Permitir mínimo y máximo.

H. Desplegable
- Select con opciones configurables.

I. Matriz
Permitir definir:
- Filas.
- Columnas.
- Tipo de selección por fila.
- Una respuesta por fila.

Ejemplo:

Pregunta:
"Evalúa los siguientes aspectos"

Filas:
- Facilidad de uso
- Rapidez
- Soporte
- Claridad del material

Columnas:
- Muy insatisfecho
- Insatisfecho
- Neutral
- Satisfecho
- Muy satisfecho

Cada fila debe permitir seleccionar una sola opción.

J. Multiselección dependiente
Crear listas encadenadas donde las opciones del siguiente nivel dependan de la selección anterior.

Ejemplo:

Nivel 1: Banca
- Banca Personal
- Premier
- RBB Digital

Nivel 2: Producto
Si selecciona Banca Personal:
- Tarjeta de crédito
- Crédito sin garantía
- Portabilidad
- Nómina

Nivel 3: Recurso
Si selecciona Tarjeta de crédito:
- Guía comercial
- Argumentos de venta
- Manejo de objeciones
- Presentación

Permitir selección múltiple cuando se configure.

4. LÓGICA CONDICIONAL
Cada pregunta debe poder tener reglas del tipo:

SI respuesta = X
ENTONCES:
- Mostrar pregunta Y.
- Ocultar pregunta Y.
- Ir a pregunta Z.
- Finalizar encuesta.

Ejemplo:

Pregunta:
"¿Actualmente utilizas Productivity Suite?"

Respuestas:
- Sí
- No
- No aplica

Reglas:
- Si "Sí" → mostrar pregunta 5.
- Si "No" → mostrar pregunta 6.
- Si "No aplica" → finalizar encuesta.

La lógica debe ser configurable sin cambiar código.

5. PANEL DE CONFIGURACIÓN DE PREGUNTA
Al seleccionar una pregunta, mostrar un panel lateral o sección editable con:

- Tipo de pregunta.
- Texto de la pregunta.
- Obligatoria Sí/No.
- Opciones de respuesta.
- Orden aleatorio Sí/No.
- Permitir Otro Sí/No.
- Máximo de caracteres.
- Mínimo de caracteres.
- Máximo de selecciones.
- Mínimo de selecciones.
- Configuración de lógica condicional.

6. VISTA PREVIA
Agregar una vista previa de cómo verá la encuesta el usuario.

Permitir:
- Desktop.
- Tablet.
- Móvil.

7. VERSIONADO
La encuesta debe soportar versiones.

Regla:
Una encuesta publicada que ya tenga respuestas no debe sobrescribirse directamente.

Si se modifica:
- Crear nueva versión.
- Mantener histórico de la versión anterior.

Ejemplo:
Encuesta Comercial
- Versión 1 publicada
- Versión 2 borrador

8. RESPUESTAS
Guardar las respuestas de forma flexible.

NO crear columnas:
pregunta1
pregunta2
pregunta3

Diseñar un modelo dinámico.

Proponer entidades similares a:

Survey
SurveyVersion
Question
QuestionType
QuestionOption
ConditionalRule
SurveyResponse
QuestionResponse
DependentOption

9. RESULTADOS
Crear una sección de resultados por encuesta.

Mostrar:
- Total de respuestas.
- Tasa de respuesta.
- Respuestas pendientes.
- Fecha de inicio.
- Fecha de cierre.

Por tipo:

Opción única:
- Conteo.
- Porcentaje.
- Gráfica de barras.

Selección múltiple:
- Conteo por opción.
- Porcentaje por opción.

Texto libre:
- Lista de respuestas.
- Buscador.

Matriz:
- Resumen por fila y columna.

10. PUBLICACIÓN
Permitir configurar:
- Fecha de inicio.
- Fecha de cierre.
- Una respuesta por usuario o múltiples.
- Encuesta anónima Sí/No.
- Requiere usuario autenticado Sí/No.
- Mensaje inicial.
- Mensaje final.

11. SEGMENTACIÓN
Permitir definir quién puede responder.

Ejemplos:
- Ejecutivos.
- Gerentes.
- Segmento.
- Región.
- Sucursal.
- Usuarios específicos.

12. EXPERIENCIA DE USUARIO
Priorizar:
- Claridad.
- Pocos clics.
- Diseño limpio.
- No saturar la pantalla.
- Usar cards y accordions para organizar configuración avanzada.
- Las reglas condicionales deben ser fáciles de entender visualmente.
- El administrador debe poder construir una encuesta sin conocimientos técnicos.
